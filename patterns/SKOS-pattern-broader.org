 - dcterms:description :: This ontology is a modelling pattern for a SKOS concept hierarchy: one skos:Concept individual is narrower than another, related by skos:broader. *** How to apply this pattern                                   :nodeclare:
:PROPERTIES:
:ID: SKOS-pattern-broader-howto
:END:

The generic procedure is in [[file:pattern-framework.org::*Applying a pattern: the generic procedure][Applying a pattern: the generic
procedure]]. Specific to /this/ pattern:

- *The relation comes from the outline, not from a row.* Setting
  ~:ELOT-subheading-relation: skos:broader~ in the *broader* concept's
  property drawer makes every nested subheading assert
  ~skos:broader~ back to it. Do not also write a ~Facts ::
  skos:broader ...~ row on the narrower concept: that would state the
  same thing twice.
- *Concepts are individuals, not classes.* SKOS is a vocabulary of
  ~skos:Concept~ *instances*; ~skos:broader~ is an object property
  between individuals, not ~rdfs:subClassOf~. The declarations
  therefore belong in the target file's ~Individuals~ section, and
  every concept needs an explicit ~Types :: skos:Concept~ row.
- *Both slots are bind-first.* Concept schemes are normally built up
  incrementally, so a concept being placed under a broader one usually
  already exists -- and the broader one almost always does. Search
  before minting.
- *~skos:broader~ is not transitive.* SKOS deliberately keeps it
  intransitive and offers ~skos:broaderTransitive~ as the transitive
  super-property. Assert only the direct link, as the outline nesting
  does; do not add skip-level rows.

*** Cardinality: what this pattern commits to                    :nodeclare:
:PROPERTIES:
:ID: SKOS-pattern-broader-cardinality
:END:

The commitment is *one broader link* per application. Multiple
narrower concepts under one broader concept need no repeat
application: outline nesting takes any number of subheadings.
Poly-hierarchy (one concept under two broader concepts) does need a
second application, and
because a resource may be declared by only one heading, the second
link must be written as an explicit ~Facts :: skos:broader ...~ row on
the narrower concept -- the one exception to the rule above.

*** Required constants                                          :nodeclare:
:PROPERTIES:
:ID: SKOS-pattern-broader-constants
:END:

Both from ~http://www.w3.org/2004/02/skos/core~:

- ~skos:Concept~ -- the type of both individuals.
- ~skos:broader~ -- the relation, asserted by outline nesting.

*** var:broaderConcept
:PROPERTIES:
:ELOT-subheading-relation: skos:broader
:END:
 - Types :: skos:Concept
 - pattern:action :: BIND_OR_MINT
 - pattern:instruction :: The broader concept. Bind-first: in a concept scheme built up over time the broader concept almost always exists already, and minting a second one for the same concept is the common error here. Copy the :ELOT-subheading-relation: drawer property to the new heading; it is what makes the nesting state skos:broader.

**** var:narrowerConcept
 - Types :: skos:Concept
 - pattern:action :: BIND_OR_MINT
 - pattern:instruction :: The narrower concept, declared as a subheading of the broader one. Bind-first: prefer an existing concept. Placing an existing concept under a new broader one means MOVING its heading, not declaring it a second time.
