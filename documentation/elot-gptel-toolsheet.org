* Error contract

Every tool reports problems in its returned text; no tool signals a
Lisp error out to gptel.

** Shared behaviour

- *Read-only tools* end in a handler that turns any error into a
  single =ERROR: <message>= line.
- *Mutating tools* share one write-back path
  (=elot-gptel--apply-mutation=): apply, save, revalidate; on
  revalidation failure the file is restored and the tool returns
  =ERROR: revalidation failed -- changes rolled back= plus the
  diagnostics; on success =OK: ...= plus the revalidation report.
- *Path guard.*  Every file-taking tool resolves its =file= argument
  against the current project and refuses with
  =elot-gptel: refusing path outside project:= /
  =elot-gptel: file not found:=.
- *ROBOT absent.*  ROBOT-backed tools refuse uniformly with
  =elot-gptel: ROBOT not available -- set `elot-robot-jar-path'=.
- *Side-effects gate.*  Gated tools refuse uniformly with
  =... refused -- side effects disabled (set
  `elot-gptel-allow-side-effects' ...)=.
- *Composite checkers* (=elot_check=, =elot_axiom_check=) return a
  multi-stage report; a failing stage is prefixed =FAIL:= or
  =FAIL at stage:= inside an otherwise normal report.
